# 메뉴 페이지 아코디언 레이아웃 설계

날짜: 2026-06-08
범위: `/menu` 페이지의 `MenuCategoryTabs` + `MenuCard` 재구성

## 배경 / 문제

`/menu` 페이지에는 시그니처 메뉴 4개(통돼지바베큐, 통삼겹바베큐, 해물모듬, 훈제오리)가 세로로 적층돼 있다. 각 카드는 16:9 큰 이미지 + 카테고리 배지 + 이름 + 설명 + 가격 칩 + 인원별 가격표(최대 7행) + 전화 CTA로 구성돼 카드당 약 1,020px 높이를 차지한다. 4개 합 약 4,150px = 화면 4~5번 스크롤이 필요해 사용자가 어떤 메뉴가 있는지 한눈에 파악하기 어렵다.

## 목표

- 첫 진입 시 데스크탑 한 화면에서 4개 메뉴를 모두 인지할 수 있다.
- 메뉴마다 풍부한 정보(이미지·설명·인원별 가격·CTA)는 그대로 유지하되, 사용자 요청에 따라 펼쳐서 본다.

## 결정사항

| 항목 | 결정 |
|------|------|
| 패턴 | 아코디언 — 각 카드가 독립적으로 펼침/접힘 |
| 정보 우선순위 (접힌 상태에서 보이는 것) | 썸네일 + 메뉴명 + 시작가 |
| 펼침 정책 | 여러 개 동시 펼침 가능 / 모두 접힘도 허용 |
| 기본 상태 (첫 진입) | 첫 메뉴(통돼지바베큐)만 펼침, 나머지 3개 접힘 |
| 애니메이션 | 부드러운 높이 전환 (200ms ease), 최신 브라우저에서만 적용, 구형은 즉시 스냅 (graceful degradation) |
| 인원별 가격표 인분 텍스트 색상 | 검정 (#000) — 기존 `text-fg` (warm dark) → `text-black` |

## 레이아웃

### 접힌 카드 (Collapsed) — 약 76px 높이

```
┌────────────────────────────────────────────────────────────────────┐
│ [썸] [시그니처]                                       40인분          ▾  │
│ [48] 메뉴명                                       900,000원~              │
└────────────────────────────────────────────────────────────────────┘
```

- 좌측 썸네일 48×48 정사각 (rounded)
- 카테고리 배지 (`시그니처` 등)
- 메뉴명 (text-base bold, text-fg)
- 우측 시작가 (`priceText`, brand orange #c2410c, font-bold)
- 맨 오른쪽 ▾ 화살표

### 펼친 카드 (Expanded) — 약 400px 높이

```
┌────────────────────────────────────────────────────────────────────┐
│ [썸] [시그니처]                                       40인분          ▴  │
│ [48] 메뉴명                                       900,000원~              │
├────────────────────────────────────────────────────────────────────┤
│  ┌──────────────────────┐  설명 문구                                  │
│  │                      │                                              │
│  │   큰 이미지            │  인원별 가격                                │
│  │   (16:9)             │  ┌──────────────────┐                       │
│  │                      │  │ 40인분  900,000원 │  ← "인분" #000          │
│  └──────────────────────┘  │ 60인분  1,100,000원│                       │
│                            │ ⋯                  │                       │
│                            └──────────────────┘                       │
│                            * 장소·구성에 따라 변동될 수 있습니다.        │
│                            [📞 전화 견적 문의]                          │
└────────────────────────────────────────────────────────────────────┘
```

- 헤더는 접힌 상태와 동일 (썸네일·이름·가격 그대로 보이고 ▾ 가 ▴ 로 회전)
- 본문 grid (`md:grid-cols-[1.3fr_1fr]`)
  - 좌: 큰 이미지 16:9
  - 우: 설명 → 인원별 가격표 (인분 텍스트 #000) → 보충 문구 → 전화 CTA
- 모바일(<768px)에서는 본문 grid가 1열 스택으로 변환 (이미지 위, 가격표 아래)

## 기술 선택

**HTML 네이티브 `<details>` / `<summary>` 사용.**

- React 클라이언트 컴포넌트 불필요 — 현재 SSR 서버 컴포넌트 유지.
- `<details open>` 속성으로 첫 카드 기본 펼침 처리.
- `name` 속성 사용하지 않음 → 각 details 독립 → 자동으로 다중 펼침 허용.
- 부드러운 높이 애니메이션은 CSS만으로 구현:

```css
:root {
  interpolate-size: allow-keywords;
}

details::details-content {
  block-size: 0;
  overflow: clip;
  transition: block-size 200ms ease,
              content-visibility 200ms ease allow-discrete;
}

details[open]::details-content {
  block-size: auto;
}
```

- 지원 브라우저: `interpolate-size` 와 `::details-content` 모두 지원하는 환경(Chrome 131+ / Safari 18.2+ / Firefox 133+ 정도, 정확한 버전은 구현 시 caniuse 재확인) 에서 부드럽게 전환. 미지원 환경에서는 transition 가 무시돼 즉시 스냅 — 기능적 차이 없음.
- 접근성: `<details>`/`<summary>`는 키보드(Space/Enter)·스크린리더(`aria-expanded`)를 자동 지원.

## 영향받는 파일

1. **`src/components/menu/MenuCard.tsx`**
   - `<article>` → `<details>` 변경
   - 헤더 영역을 `<summary>` 로 마크업 (썸네일·배지·이름·가격·화살표)
   - 펼침 본문 (이미지 + 설명 + 가격표 + CTA) 을 `<summary>` 다음 형제 div로 배치
   - 모바일에서 가격표를 `<details>` 로 감싸던 기존 중첩 제거 (펼친 본문 안에서 항상 노출)
   - `PricingTable` 의 `text-fg font-medium` → `text-black font-medium`
   - 기존 prop `preload` 유지 + 새 prop `defaultOpen?: boolean` 추가 (첫 카드만 `true`)

2. **`src/components/menu/MenuCategoryTabs.tsx`**
   - `<MenuCard ... defaultOpen={index === 0} />` 로 변경
   - `preload` 도 그대로 `index === 0` 유지

3. **전역 CSS** (`src/app/globals.css` 또는 동등 위치)
   - `interpolate-size: allow-keywords` + `::details-content` 트랜지션 룰 추가
   - `<summary>`의 기본 `list-style: none` + 커스텀 화살표 회전 룰

## 예상 높이 (데스크탑 첫 진입)

- 펼친 카드 1개: 헤더 76 + 본문 ≈ 320 = **약 400px**
- 접힌 카드 3개: 76 × 3 = **228px**
- 카드 간 gap (3 × 8): **24px**
- 섹션 헤더 + 패딩: ~120px
- **총합 ≈ 770px** — 데스크탑 뷰포트(800–900px) 안에 들어옴

## 비목표 (Non-goals)

- URL 딥링크(`/menu#tong-dwaeji` → 자동 펼침)는 이번 범위에서 제외.
- 추가 메뉴 카테고리(한우, 흑돼지 등)는 현재 데이터에 없으므로 미고려.
- 가격표 외 추가 사진/갤러리는 펼침 본문에 추가하지 않음.

## 위험 / 트레이드오프

- **여러 개 동시 펼침이 페이지를 길게 만들 수 있음.** 한 화면 보장은 첫 진입 시점만이며, 사용자가 비교를 위해 추가로 펼치면 스크롤이 생긴다. 이는 "비교 자유도" 와 "초기 압축" 간 trade-off로 받아들임.
- **`::details-content` 미지원 브라우저에서는 애니메이션이 즉시 스냅.** 기능엔 영향 없음.
- **모바일에서 펼친 카드 본문이 세로 스택되면서 길이가 길어짐.** 그래도 한 번에 1~2개만 열고 보는 사용 패턴이라 큰 문제 아님.

## 테스트 계획

- 단위: 현재 `MenuCard` 에 대한 테스트가 있다면 마크업 변경 반영. 없다면 새로 만들지 않음.
- 수동:
  - 데스크탑(≥1024) 한 화면에 헤더 + 4 카드(1 펼침 + 3 접힘)가 들어오는지 확인
  - 첫 카드가 기본 펼침 상태로 진입하는지
  - 여러 카드 펼침/접힘 동작
  - 모바일(<768) 펼친 본문이 1열로 스택되는지
  - 인원별 가격표의 "40인분" 등이 검정으로 표시되는지
  - 키보드만으로(Tab·Space·Enter) 펼침/접힘 가능한지
